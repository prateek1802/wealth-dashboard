NPS NAV DISCREPANCY — FULLY DIAGNOSED, ROOT CAUSE CONFIRMED EXTERNAL:
Multi-day investigation ruled out every app-side cause one by one (fetch logic,
DB writes, derived-corpus math, caching, units-count accuracy all independently
verified correct) before finding the real cause: npsnav.in's own data was
genuinely stuck for 2+ days (confirmed directly on their site: "NAV updated:
24-08-2026" banner while checking on the 26th-27th). The app's misleading
fetch-timestamp-as-"as of"-date masked this. A GitHub issue was drafted for
npsnav.in's maintainer. Fix for the masking problem itself (switch to the
"Detailed" endpoint, store the real last-updated date, add a visible staleness
warning) is fully spec'd — see Section 4, still not built.

Holdings Hub (replaces old sidebar dropdown) — done, verified clean, old logic
genuinely removed not left dangling.

A. CAGR ZERO-SNAPSHOT FIX (one paragraph, ready as-is):
   "In src/app/(app)/analytics/page.tsx, CAGR is stuck permanently showing 'Need
   a positive starting value and a positive time span' because firstSnapshot =
   sortedSnapshots[0] picks the chronologically first snapshot with no regard
   for its value, and this account's actual first two snapshots (2026-08-14 and
   2026-08-15) legitimately have netWorth = 0 (recorded before real holdings
   were added on this deployment) — calculateCAGR() in
   src/lib/calculations/returns.ts correctly refuses to compute from a zero base
   (beginValue <= 0 guard), so it's stuck on those two entries forever even
   though Aug 16 onward is perfectly good data. Fix: when selecting the CAGR
   starting snapshot, skip past any leading snapshots with netWorth <= 0 and use
   the first one with a positive value instead of unconditionally using
   sortedSnapshots[0] — recompute years from that same adjusted starting
   snapshot's date, not the original zero-value one. Add a test covering a
   snapshot series that starts with one or more zero-value entries followed by
   real values, asserting CAGR computes successfully using the first positive
   entry as the base."
