5B. NEW FEATURE, SPEC'D — ACTIVE SIPs FOR MORE ACCURATE PROJECTIONS
====================================================================================
Confirmed root gap in code: projectFutureValue() (returns.ts) is a pure
lump-sum compound formula with zero concept of ongoing contributions —
understates future wealth for anyone actively SIP-investing. Mirrors a
pattern that already works for NPS (monthlyContribution feeding its own
projection chart); this extends the same idea to regular securities holdings.

Decisions locked in: projections only, no reminder functionality (separate,
previously-discussed idea, deliberately not bundled in); a SIP continues
indefinitely once added, with a "mark as stopped" action rather than a
future end-date field.

Full spec written (ACTIVE-SIPS-PROMPT.txt): new active_sips table (added to
the existing audit-trigger loop for free history/recoverability), a new
projectFutureValueWithSIP() calculation requiring validation against a
hand-checked reference case before shipping (explicit instruction given,
given this project's history of subtle financial-formula bugs), a compact
management UI (dropdown of currently-held assets + monthly amount, reusing
existing getAssetDisplayLabel/getHoldings utilities rather than duplicating
them), and wiring into growth-projection.tsx's existing per-holding and
portfolio-level projection calls. Not yet built as of this report.
