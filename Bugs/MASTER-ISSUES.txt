🔴 OPEN — ready to patch directly (small, contained)
====================================================================
1. Dashboard "Day Change" always shows ~₹0.
   CAUSE: dashboard/page.tsx calls snapshotService.recordTodaysSnapshot() first (which
   upserts today's snapshot), then calls getPortfolioSummary() again to render the page.
   Inside getPortfolioSummary() (~line 132), "previous" for dayChange is just the
   chronologically-last snapshot — but today's just-written row is now that last one,
   so it diffs net worth against itself.
   FIX: filter to snapshotDate < today before picking "previous".

2. MF Equity / MF Debt labels too long/visually heavy in cards.
   CAUSE: src/constants/asset-types.ts — "Mutual Fund (Equity)" / "Mutual Fund (Debt)",
   single source of truth used everywhere.
   FIX: shorten in this one file (e.g. "Equity MF" / "Debt MF").

3. Vercel Analytics and Speed Insights not enabled.
   CONFIRMED: no @vercel/analytics / @vercel/speed-insights in package.json, no
   <Analytics/>/<SpeedInsights/> in src/app/layout.tsx.
   FIX: install both packages, add both components to root layout.

4. Transaction history has no "View more" / pagination — renders unbounded (267+ rows
   seen in one screenshot).
   FIX: cap initial render (e.g. 25-50 rows) with a "View more" button, or real pagination.

5. Goals — same icon-overlap bug as the already-fixed Bank Account/FD cards.
   CAUSE: goals-view.tsx wraps GoalCard in a relative div with an absolutely-positioned
   delete button; GoalCard's own header can render a "by {targetDate}" label in that same
   top-right spot, so they can collide.
   FIX: same pattern already used for FD/bank account cards — move delete into the card's
   own header flex row instead of absolute positioning.

6. Watchlist shows no current price, despite the data already existing.
   CAUSE: Asset already has currentPrice/currentPriceUpdatedAt; WatchlistItem includes
   the full asset — it's just never rendered on the watchlist card. Only target
   price/stop-loss are shown, with nothing to compare them against.
   FIX: display item.asset.currentPrice + currentPriceUpdatedAt on each card.

7. Goals have no edit capability, only add/delete.
   No updateGoalAction exists anywhere. To change targetAmount/currentAmount/targetDate,
   the only option is delete-and-recreate. Same class of gap "transaction edit" was
   before it got fixed — mirror that pattern.

8. Watchlist prices are never refreshed even after #6 is fixed.
   No refresh mechanism reaches watchlist assets — refreshLivePricesAction is scoped to
   actual holdings (quantity > 0) only, no AssetRefreshButton anywhere in the watchlist
   feature.
   FIX: add a per-item or page-level refresh button calling refreshLivePricesAction()
   scoped to the watchlist's asset IDs.

9. Refresh-all button — placement question.
   A page-level "Refresh Prices" button already exists on the Portfolio page and refreshes
   all currently-displayed holdings. But the request ("page with cumulative XIRR, has a
   lot of empty space") sounds like the Dashboard's XIRRCard — confirmed genuinely sparse
   (just a label + number, generous padding, no action).
   NEEDS: confirm whether the Portfolio-page button already satisfies this, or whether a
   refresh control specifically belongs on/near the Dashboard's XIRRCard.

10. Liabilities section not loading.
    Checked page, service, repository, schema (both schema.sql and sync-schema.sql), RLS
    policy, and view component — everything is internally consistent in source. Likely a
    live/deployment issue (schema drift not yet synced, an RLS/auth session issue, or a
    transient error), not a code bug visible from static source.
    NEEDS: browser console error, network tab response, or Vercel function logs from an
    actual failed load.

11. Sharpe/Sortino ratios likely distorted.
    risk.ts hardcodes Math.sqrt(252) (correct only for daily return series), but snapshots
    are written opportunistically (whenever the dashboard loads), not daily — so real
    intervals are irregular and usually longer than a day. Numbers on Analytics page are
    probably inflated/wrong relative to what they claim to represent.
    NEEDS A DECISION: derive the annualization factor from actual average snapshot
    interval, or just label these as unreliable until snapshot cadence improves.

12. Backup/Restore silently excludes 2 of 11 data tables — price history and portfolio
    snapshots.
    Checked backup.service.ts's ENTITY_LABELS against all 11 repositories —
    price-history.repository.ts and snapshots.repository.ts are never referenced in
    backup export/import. A "full" restore on a new device would silently lose the entire
    price chart history (documented elsewhere as never re-fabricated once lost) and the
    snapshot history that Day Change, the performance graph, and Sharpe/Sortino all
    depend on.
    NEEDS A DECISION: add both tables to backup/restore, or explicitly document this as a
    known limitation so a "full backup" claim isn't misleading.

13. Dropdown → clickable-card view for holdings (asset class → card view → individual
    holdings on click).
    No dropdown component (Radix Dropdown/Accordion/Collapsible) found by name in
    portfolio-view.tsx or sidebar layout — likely refers to the sidebar's per-asset-class
    links per PROJECT-STATUS.md. UI/IA redesign, not a bug.
    NEEDS: a screenshot or screen-recording of the current interaction before scoping
    the rebuild.
