2. CONSISTENCY BUGS — "SAME NUMBER, DIFFERENT VALUE IN DIFFERENT PLACES"
====================================================================

✅ Net worth itself IS consistent everywhere — single getPortfolioSummary() source,
   verified across Dashboard and Analytics, NPS uses live derived corpus correctly.

⚠️ CAGR mixes old- and new-methodology numbers invisibly. Compares your oldest
   stored snapshot (computed under old, less-correct logic — especially old NPS
   corpus handling) against today's freshly-computed net worth. Could show an
   artificial jump that's really just "the math got more correct," not real growth.
   Fix: a caption noting pre-rewrite snapshots may not be directly comparable, or
   accept as a known one-time distortion.

⚠️ "Refresh all" doesn't mean all. Dashboard's button only calls
   refreshLivePricesAction() (securities) — zero awareness NPS live NAV refresh
   exists. Confirmed still the case.

⚠️ NPS "as of" timestamp is misleading — shows fetch time, not the NAV's real date
   (npsnav.in's "Simple" endpoint returns no date at all). A "Detailed" endpoint
   exists (/api/detailed/{scheme_code}) with a genuine "Last Updated" field — switching
   would make the displayed date trustworthy instead of always looking fresh.

CHECKED, FOUND CONSISTENT: XIRR (Dashboard vs Analytics), holdings/currentValue
(single computeHoldings() source), NPS page has no separate XIRR to conflict.

3. MAJOR BUGS / GAPS — CORE APP (re-verified against current code)
====================================================================

❌ No audit trail for financial record edits/deletes. Highest real risk — silent,
   irreversible data loss on financial history is currently possible.

❌ CSV transaction import isn't idempotent. Re-uploading the same file duplicates
   transactions silently. Fix pattern already proven in your own NPS importer —
   just needs porting to this older path.

❌ Backup/Restore silently excludes price_history and portfolio_snapshots — 2 of 11
   tables never backed up, despite being marketed as a full JSON backup.

❌ Liabilities section reported as not loading. Checked page/service/repository/
   schema/RLS — all internally consistent in source. Likely a live/deployment issue
   (schema drift, auth session, transient error), not a code bug visible from static
   source. Needs a real browser console error or Vercel log to progress further.

❌ Dashboard fetches the same base data ~5x per page load (assets/transactions
   re-queried independently by getPortfolioSummary/getAssetAllocation/
   getTopHoldings/getSegregatedBreakdown instead of sharing one computed result).
   Not currently a speed problem; compounds as transaction history grows.

❌ No error boundaries (error.tsx) anywhere in the App Router — a thrown Server
   Component shows Next.js's generic crash page.

❌ No loading.tsx anywhere — no route-level streaming; navigation shows a blank
   screen until a page's full data fetch completes.

❌ No server-side error logging anywhere — zero console.error calls across any
   service/action file.

❌ Vercel Analytics and Speed Insights not installed — no @vercel/analytics or
   @vercel/speed-insights in package.json, nothing in layout.tsx.

❌ No auto-refresh at market close (cron). Confirmed no vercel.json, no scheduled
   workflow — prices only refresh opportunistically when the app is opened. Needs
   real new infra (Vercel Cron Job + protected API route), not a code-only patch.
