====================================================================
✅ #8 — Rate limiting / graceful degradation for external price APIs
====================================================================
FULLY FOLLOWED, better than expected. refreshLivePricesAction() (portfolio/actions.ts):
  - Fetches sequentially (for...of + await), not Promise.all — avoids bursting free
    APIs with simultaneous requests.
  - Per-asset failure isolation: each quote fetch is independently try/caught inside
    getLiveQuoteForAsset(); a failed fetch adds the symbol to a `skipped` list and
    continues, rather than the whole refresh throwing.
  - Old price is left untouched on failure — never overwritten with null/zero.
This is a genuinely well-built pattern for working against unofficial/free data
sources.

====================================================================
⚠️ #1 — Money as floating point, not decimal-safe
====================================================================
NOT FOLLOWED, but likely low real-world impact so far. No decimal.js/big.js/
bignumber.js anywhere in package.json. All financial summation across
calculations/*.ts (holdings.ts, lots.ts, pnl.ts, returns.ts, risk.ts, allocation.ts)
uses plain JS `Number` + `.reduce()`. This is the standard "just use floats" approach,
which works fine for small transaction counts and typical INR amounts, but is a latent
precision-drift risk as transaction volume grows over years (which, given this is a
personal long-term wealth tracker, it will). Not urgent, but worth knowing it's there
rather than discovering it as an unexplained few-rupee mismatch five years from now.

====================================================================
❌ #2 — Append-only / audit trail for financial record edits
====================================================================
NOT FOLLOWED. No audit_log or equivalent table anywhere in schema.sql. Transaction
edits and deletes (transactions.repository.ts) are genuine in-place UPDATE/DELETE with
no history retained. If a transaction is edited or deleted by mistake, there's no way
to see what it was before, or that a change happened at all — updated_at only tells
you *that* something changed, not *what* changed. Real cost: this directly undermines
trust in historical XIRR/P&L figures, since there's no way to verify they weren't
computed against data that later got silently altered.

====================================================================
❌ #3 — Idempotency on external data imports
====================================================================
NOT FOLLOWED for the existing CSV transaction import (import-csv-dialog.tsx /
transactions/actions.ts) — no dedup/duplicate-detection logic found. Re-importing the
same CSV twice would create duplicate transactions with no warning. This is exactly
the class of bug the NPS statement re-upload feature (still unbuilt) is specifically
designed to avoid — worth confirming the existing CSV import gets the same treatment,
or at minimum a manual warning that re-uploading isn't safe, since right now nothing
stops it from silently duplicating data.

====================================================================
✅⚠️ #4 — Derived values recomputed, not manually cached (mixed)
====================================================================
ONE CONFIRMED VIOLATION (already found and being fixed): NPS current_corpus was/is a
manually-synced cached total rather than derived live from contributions — the exact
bug this project spent significant effort diagnosing and is mid-fix for. The schema
rewrite already planned (units × NAV, corpus derived at read time) is the correct fix.
CHECKED FOR SIMILAR PATTERNS ELSEWHERE: liabilities.amountOwed looked suspicious at
first glance but is NOT the same bug — it's directly user-edited by design (you
manually update your credit card/loan balance when it changes), not something meant
to auto-derive from an underlying transaction log that silently fails to sync. No
other instance of the NPS-style bug pattern found elsewhere in the codebase.
